    \section{description}\label{sec:description}
    This document describes how to configure OASYS for use as a service provider in a SAML federation. It is assumed that the reader has a basic understanding of SAML and how it works. It is also expected that an identity provider using SAML 2.0 is already set up and configured. This document will not cover how to set up an identity provider or how to configure it to work with OASYS, but will focus on the configuration of OASYS itself.

    \section{configuration}\label{sec:configuration}
    First, make a copy of the file "\kw{conf/ssodata.default}" to "\kw{conf/ssodata.ini}". This file contains the SAML configuration for OASYS. Open the file and edit the following entries to match your SAML configuration:
    \begin{properties}
    \hline
        Issuer & This is the entity ID of your OASYS instance. It should be a unique identifier that represents your OASYS instance in the SAML federation. It is recommended to use a URL as the entity ID, but it can be any string.\\
        SSOLoginURL & This is the URL of the SSO login endpoint of your identity provider. This is the URL that OASYS will redirect users to when they need to authenticate. It is generally found in the metadata of your identity provider (check for the \kw{SingleSignOnService} element).\\
        SSOLogoutURL & This is the URL of the SSO logout endpoint of your identity provider. This is the URL that OASYS will redirect users to when they log out. It is generally found in the metadata of your identity provider (check for the \kw{SingleLogoutService} element).\\
        IDPhost & This is the hostname of your identity provider. It is used to determine if a user is authenticated or not based on the presence of a SAML session cookie. It should match the hostname of your identity provider (e.g.\ idp.example.com).\\
        IDPIssuerID & This is the entity ID of your identity provider. It is generally found in the metadata of your identity provider (check for the \kw{entityid} element).\\
        IDPuidStr & This is the name of the SAML attribute that contains the unique identifier of the user in your identity provider. It is used to map the SAML user to a user in OASYS. It is already set by default to "urn:oid:0.9.2342.19200300.100.1.1" which corresponds to the object identifier of the \kw{uid} attribute in LDAP. If the IdP you are connecting to uses a different key, you have to replace this value for OASYS to be able to extract the user identifier from the SAML assertion.\\
        sigAlgo & This is the signature algorithm that the identity provider uses to communicate with OASYS. The default value is "OPENSSL\_ALGO\_SHA1" which corresponds to RSA-SHA1. If your identity provider uses a different signature algorithm, you have to replace this value for OASYS to be able to read the SAML requests correctly. See below for a list of possible values.\\
        ACS & This is the Assertion Consumer Service (ACS) URL of your OASYS instance. It is the URL that the identity provider will redirect users to after they have authenticated. It should be in the format \kwm{"https://\kwo{your-domain}/\kwo{path-to-oasys}/editor/sso.php"}. Make sure to replace \kwo{your-domain} and \kwo{path-to-oasys} with the actual hostname of your OASYS instance.\\
        & In most cases the ACS can be left blank as it will be determined automatically. However if your server is using some custom domain/URL mapping or rewriting, you might need to set this value explicitly for the SAML integration to work correctly. Essentially it should be how the outside world sees the url that leads to the path \kwm{editor/sso.php} of your OASYS instance.\\
    \hline
    \end{properties}

    Once this is done, you can register your SP in the IdP. The metadata URL is as follows:\\
    \kwm{https://\kwo{your-domain}/\kwo{path-to-oasys}/editor/tools/sp\_metadata\_writer.php}\\[0.3cm]

    Last but not least, switch on SAML support in the settings of OASYS. To do this navigate to \kw{System Settings} (in most OASYS setups this will only be accessible to superadmin users), then scroll down to the \kw{SSOSysActive} option and set it to \kw{true}. This will enable SAML support in OASYS and allow back end users to authenticate using SAML\@.
